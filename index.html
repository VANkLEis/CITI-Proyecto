Arranque en 3 pasos

Tres pasos. Un comando.

La primera vez construye la imagen y siembra la base demo. Las siguientes solo levanta los contenedores.

01

Abre Docker Desktop

Espera a que el motor de Docker esté en marcha. El contenedor de PostgreSQL 16 se crea solo.

02

Ejecuta iniciar_citi.bat

Doble clic en la raíz del proyecto. Construye la imagen, migra, siembra los datos y espera a Django.

iniciar_citi.bat
03

Abre localhost:8000

El script abre el navegador al terminar. Si no lo hace, usa el botón o escribe la dirección.

http://localhost:8000

Alternativa manual desde la raíz: docker compose up -d --build. Para ver el arranque: docker compose logs -f web.

Patrón arquitectónico

MVT: Model · View · Template

Todo el proyecto Django vive en backend/. La raíz no contiene apps duplicadas ni una segunda implementación.

Model

Datos y reglas

Entidades, relaciones y validaciones de negocio. Cada app concentra sus modelos y migraciones.

  • backend/accounts/models.py
  • backend/scheduling/models.py
  • backend/portal/models.py
View

Control y negocio

Recibe la petición, aplica permisos y reglas, consulta los modelos y elige la plantilla.

  • backend/portal/views_public.py
  • backend/portal/views.py
  • backend/portal/views_solicitudes.py
Template

HTML renderizado

Plantillas Django con herencia, partials y datos del contexto. No hay SPA ni frontend separado.

  • backend/templates/portal/landing.html
  • backend/templates/portal/public_base.html
  • backend/templates/dashboard_base.html

Flujo de una petición a la portada

GET /
  └─ backend/config/urls.py       include('portal.urls')

          └─ backend/portal/views_public.py
              ├─ backend/portal/models.py          ProyectoPortafolio · Taller
              └─ backend/templates/portal/landing.html  respuesta HTML

Mapa de carpetas

Una sola raíz, tres carpetas.

El código ejecutable, la documentación y las herramientas de generación quedan separados.

CITI-Proyecto/
├─ index.html                 punto de entrada visual
├─ iniciar_citi.bat           arranque en Windows
├─ Dockerfile · docker-compose.yml
├─ backend/                   único proyecto Django (MVT)
│  ├─ config/                 settings.py · urls.py · wsgi.py
│  ├─ accounts/               usuarios, empresas, perfiles
│  ├─ scheduling/             franjas, citas, solicitudes
│  ├─ portal/                 vistas públicas, paneles, triage
│  ├─ templates/              landing.html y plantillas
│  └─ static/                 CSS, JS, imágenes, videos, fuentes
├─ docs/
│  ├─ demo/                   credenciales y guion
│  ├─ presentacion/           entregables finales
│  ├─ sustentacion/           diagramas y fuentes
│  ├─ prototipo/              archivo histórico Hi-Fi
│  └─ audit/
└─ tools/                     generación de medios
Backend = única fuente de verdad Modelos, vistas, URLs y plantillas están en backend/. No hay carpetas accounts/, portal/ o scheduling/ en la raíz.
Docs = evidencia y entrega Credenciales, guion de demo, presentación final, diagramas y el archivo del prototipo visual.
Tools = no runtime Scripts reproducibles para imágenes y videos. No se copian a la imagen Docker.
